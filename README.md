# 账单有数：空白通用版与 QQ 邮箱导入

初始账本为空，不预置真实账单、邮箱、授权码或加密个人账单。用户账单记录保存在自己的浏览器，不跨设备同步。更换设备、网址或清除浏览器存储前应先导出备份。

## 当前部署状态

GitHub Pages 是静态网址，只能使用记录、邮件文件导入和日历提醒。点击“连接邮箱导入”会检查同源后台，未开通时禁用邮箱及授权码输入。**当前 GitHub Pages 网址尚不能直接读取邮箱。**

仓库包含可部署的 Node.js 邮箱后台及 render.yaml 免费试用配置。账户连接和实际后台部署尚未完成。免费配置是试用方案，不是正式运营质量或永久免费承诺。没有采购付费资源。

## 启动

使用 Node.js 22+、pnpm 11.25.0。运行 pnpm install --frozen-lockfile --ignore-scripts，然后 pnpm start。

启用环境变量 MAILBOX_IMPORT_ENABLED=true；APP_ORIGIN 为正式 HTTPS origin（不含末尾斜线），Render 可直接使用内置的 RENDER_EXTERNAL_URL。前端与后台必须同源。服务未开启时拒绝处理授权码；没有任意自定义邮箱网关地址。/healthz 用于健康检查。

## 邮箱处理

首版接受 QQ 邮箱和生成的 16 位邮箱授权码，不是 QQ 登录密码。每次点击时读取，授权码不存入浏览器或后台数据库。固定连接 imap.qq.com:993，验证 TLS，使用只读邮箱锁；不发送、删除、移动或标记已读邮件。QQ 授权码本身可能具有更广的邮箱权限。

按 90/120/180/365 天范围及账单关键词查找，再用信用卡关键词或银行发件域名缩小正文读取范围。这不代表验证了发件人身份。最多检查 12 个非垃圾、草稿、发送或已删除文件夹、60 封候选邮件；原始邮件上限 1MB。达到上限或跳过邮件时提示，不能宣称已覆盖全部最新账单。

暂不支持 PDF、截图和加密附件账单。只处理邮件文字，HTML 转文字不请求远程图片。后台不保存原始邮件、账单库或请求正文日志。候选信息及文字片段返回当前浏览器用于核对，用户确认后保存本机账单。

自动识别银行、尾号、账期、应还金额、最低还款及完整还款日。不可靠字段留空。尚未完成所有银行真实模板验证，结果必须按原文核对。重复账单仍按当前页面规则阻止重复保存。

没有定时后台同步或后台推送。关闭网页后的还款提醒需要导入手机日历并确认通知；网页标记已还不会自动取消已导入日历事件。

## 检查与边界

已检查模拟 IMAP、真实 MIME 编码解析、只读配置、同源要求、未配置时拒绝授权码、静态文件白名单、错误不回显秘密及依赖漏洞审计。浏览器流程使用虚构邮件，没有真实邮箱或授权码参与测试。

尚未验证：部署环境到 QQ 的 IMAP 连通性、真实授权登录、九家银行全部实际模板、各用户手机与大陆网络可达性。

API 只接受匹配 Origin 的 JSON 请求，不开放 CORS。最多两路并发，按连接地址限流；代理后的客户端限流需在托管平台另行配置，不能信任客户端任意提交的转发头。正式运营还需容量、滥用防护、监控、经营主体联系渠道、隐私告知和适用的备案/个人信息处理评估。海外托管涉及邮箱授权及金融信息临时处理，需按实际服务商和区域评估并告知。

Render 官方将免费实例用于试用或个人项目：空闲会休眠，有冷启动、额度及流量限制，不应据此承诺正式公共邮箱服务质量。

仓库公开，不得上传真实账单、邮件、授权码、访问口令或登录会话。授权码也不要发送到聊天中。
